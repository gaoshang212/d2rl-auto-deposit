# Auto Deposit 自动入库

**[English](README.md)** · 中文说明

给 **Reimagined** 暗黑破坏神2重制版 mod 用的 [D2RLoader](https://github.com/D2RLoader/PluginSDK) 插件。
**捡起来的东西自己进该去的地方** —— 不用按键,不用点,不用方块配方。

两个去处:

* **宝石进 mod 的宝石袋。** 只动你捡的那一颗,背包里其它松散的宝石原地不动。
* **别的进高级仓库。** 每件捡起来的物品都交给游戏自己的存入函数 —— 只要游戏认为它算高级仓库材料。
  宝石、符文、材料、方块,凡是游戏本身允许你丢进那些页签的。

一个插件,因为这是同一个决定。宝石归袋子,所以袋子开着的时候存入这条路径根本不考虑宝石,
两者永远不会抢同一件东西。

## 安装

把 `d2rl-auto-deposit.dll` 放进 `<mod>/d2rloader/plugins/`。合并需要宝石袋在背包里 ——
没袋子就没地方合并。存入需要该角色有高级仓库。

这个插件取代 `d2rl-auto-gem-bag` 和 `d2rl-auto-stash`。**不要和它们同时运行。**

## 配置

`<mod>/d2rloader/config/d2rl-auto-deposit.toml`

```toml
[auto-deposit]

gem_bag_merge_gems     = true    # 捡起宝石时合入袋子
gem_bag_merge_clusters = true    # 捡起宝石簇时合入袋子
gem_bag_ignore         = ""      # 袋子不许收的物品代码

stash_deposit          = true    # 其它物品自动放入高级仓库
stash_ignore           = "rvs rvl"   # 仓库不许收的物品代码
```

每个键都是**目的地在前、动词居中、宾语在后** —— `gem_bag_merge_gems` 和 `stash_deposit` 不用看注释
就知道属于哪一半,两个 `*_ignore` 列表则是严格对称的。

默认全开:没被忽略列表点名的东西,都会去它该去的地方。列表里是三位物品代码,用空格或逗号分隔,
就是在交易窗口里能看到的那些;同一行 `#` 之后的内容当注释。

```toml
stash_ignore = "rvs rvl"    # rvs 小紫,rvl 大紫,两种恢复药水
```

`stash_ignore` 默认是 `"rvs rvl"`,两种恢复药水 —— 这是插件默认唯一不碰的东西。游戏本身乐意收它们
(它自己的仓库检查两个都接受),所以这是插件定的规矩,不是游戏的规矩:紫药是在战斗中从腰带或背包里喝的,
捡起来就存进仓库,真要用的时候就不在手上了。想让它们也照常存进去,把列表清空即可。

这个文件是插件第一次加载时 D2RLoader 写出来的,之后**再也不覆盖**,你改的内容不会因为更新插件而丢。
**只在启动时读一次 —— 改完要重启 D2R。**

* 开关管的是**自动路径**(捡东西时自动跑的那条)。`deposit` 是你手动敲的,所以永远两件事都干,不看这个文件。
* 值不是明确的 `true` / `false` 时回落到默认(开),打错字母不会让功能悄悄失效。
* 不是恰好三个字符的条目会被**数出来并报告**,而不是截断成三个 ——
  一个悄悄表达了别的意思的列表,正是插件会忽略掉错误东西的原因。
* 每次启动都会记录读到的值:`AutoDeposit: config says gem_bag_merge_gems=true, ...`。
  如果看到 `could not read ... built-in defaults are in use`,说明文件没读上,开关是摆设。

## 控制台

* `deposit`(或者 `deposit stash`)—— 把背包格子上所有东西一次性扫进高级仓库,
  给插件加载之前就已经躺在那里的那些用。手动敲的这一遍,它拒绝的每一件都会给答复,
  汇总行还会点名留下的是哪些代码。
* `deposit bag`(或者 `deposit merge`)—— 把所有松散的宝石和宝石簇扫进袋子。
* `deposit probe` —— 读一次宝石袋的计数并写进日志,什么都不消耗。
* `deposit why` —— 只读报告:背包格子上的每个单位,SDK 说它在哪个容器、游戏对它怎么答;走查看到
  但不会交出去的那些;每种物品代码一行;最后把走查交出的格子数量,和 SDK 自己数出来的格子数量
  并排放着 —— 走查漏了东西,它会自己说出来,而不是看起来像游戏拒收。**东西不进去、日志又什么都
  没说的时候,敲它。**

## 永远不动的东西

* **宝石袋本身。** 从不存入,连裸 `deposit` 全扫也不会碰。它是宝石待的地方,把它存进去等于
  连你攒过的每一颗宝石一起交出去。这一条不可配置,因为这不是偏好问题。
* **35 种经典宝石**(碎裂到完美)。袋子对颜色和品质是瞎的 —— 每颗都只算 +1 —— 而 Grabber 只还回
  普通宝石,合并一颗完美红宝石等于用一个点数换掉它,品质再也回不来。它们原地不动,日志会说路过几颗。
* **不在背包格子上的任何东西。** 腰带、身上装备的栏位和仓库页签都挂在同一个容器下。
  对别的页面上的单位,永远不会调用任何会移动物品的东西。
* **方块。** 里面躺着的半成品配方,正是绝对不能扫走的那种东西。

## 行为细节

* 共享仓库面板开着时自动路径会避开:物品会从正在绘制的格子里消失。拾取不会丢 ——
  它留在队列里,面板一关自己就进去,或者敲 `deposit` 立刻进去。控制台命令不受这个限制,
  因为那是你自己要的,而且你正看着结果。
* 拾取和物品到手不是同一件事。游戏的拾取函数在点击被接受后就返回,物品稍后才出现 ——
  所以插件记下 id 然后去找它。顺带的结果是一次捡一堆也不会只处理一个。
* 一个宝石簇值 20-30 颗宝石 —— mod 自己的配方,每簇单独摇。
* 袋子留在原来的格子。数量没法就地改写,所以合并是拿一个装着新数量的相同袋子换掉旧的,放回旧袋子
  当时的位置。万一那个格子被拒绝,新袋子才落到第一个空格,日志会写明。
* 袋子封顶 65535,装不下的留在背包里。
* 包里有不止一个宝石袋 → 合并什么都不做,它分不清你说的是哪个。
* 存入调用本身是沉默的。`StashDeposit` 返回 void,所以一次运行最多只能诚实地说"调用返回了、没崩" ——
  真正的确认是背包里少了、页签里的堆叠涨了。

## 构建

需要 Visual Studio 2022(x64)、Ninja、CMake 3.28+。[SDK](https://github.com/D2RLoader/PluginSDK)
不用手动准备:`external/d2r-pluginsdk`(或项目旁边)有就用本地的,没有就自动从 GitHub 克隆到
`build/_deps`。想指到别处加 `-DD2RLPLUGIN_SDK_DIR=<路径>`。

```bat
build.bat
```

想让它顺手把 DLL 复制进你的 mod,指定一次,CMake 会记住:

```bat
cmake -S . -B build -DD2RL_AUTODEPOSIT_DEPLOY_DIR="<mod>/d2rloader/plugins"
```

不指定(默认空)就只编译。在 Git Bash 里要套一层
`MSYS_NO_PATHCONV=1 cmd.exe /c "cd /d <项目目录> && .\build.bat"`,否则 MSYS 会把看起来像路径的参数改掉。
复制时游戏开着的话,新 DLL 会留在旁边叫 `d2rl-auto-deposit.dll.new`,关掉游戏后改名覆盖即可。

> **不要强制结束 `D2RLoader.exe`。** 存档在它手里。

## 原理

挂钩游戏自己的拾取函数,挂钩前先校验 32 字节签名,**对不上就一个字节都不改**。拾取会把刚落进包的那件
物品的 guid 交出来;两件事都排到游戏线程上 —— 唯一支持改物品的地方 —— 而且都不在钩子里跑。

袋子那一半走一次事务:计数(ItemStatCost 386 `stacked_gem`,16 位)没法就地写,所以旧袋子加宝石进去、
新袋子出来。有一步校验不过,什么都不消耗。

存入那一半 SDK 里根本没有对应的路 —— SDK 没有把物品移进高级仓库的接口 —— 所以直接按地址调用游戏自己的
函数,在游戏线程上。一次运行从**一遍走查**开始:玩家的物品容器比背包大 —— 腰带、身上装备的栏位、方块、
每个仓库页签都挂在同一个容器下 —— 走查把整个容器走一遍,只交出**站在背包格子上**的单位;没交出去的,
任何会移动物品的东西都够不到。十六个地址,每一个都在**任何调用发生之前**按预期字节整组校验过。游戏那个
"这东西算不算高级仓库材料"的判定要的是 class id,这个号码是对**手上这件物品**直接问游戏要的,不是从
另一套枚举里拼出来再配对上去的。

签名对不上的版本,丢的是存入那一半,保住的是袋子那一半 —— 后者一个地址都不需要。
不管哪种,损失的都是功能,不是游戏。

已在 D2R 3.3.0、构建号 93847、Reimagined 3.0.10 上验证。

```
src/deposit_plugin.cpp    入口 —— 只有三个导出,别的什么都没有
src/deposit_native.*      仓库那一半直接调用的地址,以及那些调用
src/deposit_stash.*       一次入库,以及控制台要的全扫
src/deposit_gem_bag.*     袋子那笔事务 —— 只走 SDK,自己不需要任何地址
src/deposit_report.*      'deposit why' —— 只看不动的报告
src/deposit_pickup.*      拾取钩子,以及把它看到的东西送出去的队列
src/deposit_console.*     'deposit' 命令
src/deposit_config.*      配置文件,以及两半之间的路由
src/deposit_codes.h       物品代码、宝石表,以及它们的文本形式
src/deposit_common.*      上下文、线程服务、日志预算
auto-deposit.toml         默认配置,会被内嵌进 DLL
CMakeLists.txt            构建,以及可选的复制进 mod
build.bat                 找 Visual Studio、配置、编译
cmake/deploy_dll.cmake    复制那一步
external/d2r-pluginsdk    SDK,如果你在这放了一份(不进仓库)
```
